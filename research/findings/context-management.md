# Context management and token economy

A 2-3 hour research run in Claude Code fails on context rot before it fails on tokens: every tool result, fetched page and pasted subagent report stays in the lead's history and is re-read on every turn until compaction summarizes it away, and compaction keeps "your requests and key code snippets" but loses "detailed instructions from early in the conversation". The evidence opened on 2026-10-16 supports one architecture: a thin lead that holds only a plan, an index and short status lines; isolated subagents (fresh context, cheaper model where the task is mechanical) that do the reading and write findings to files; durable rules in a short project-root CLAUDE.md (re-injected from disk after compaction) and in skills (loaded on demand, re-injected up to 5,000 tokens each); and explicit size caps on what returns to the lead. Claude Code already does prompt caching, deferred MCP tool loading, tool-result clearing before summarization, and auto-compaction automatically; the plugin's job is to make the lead's history small and recoverable, not to count tokens.

## Questions and answers

### Q1. What context mechanisms does Claude Code document today, with what limits and defaults?

Confidence: high (every item below is quoted from a code.claude.com page opened 2026-10-16).

**Compaction and /compact.** "Claude Code manages context automatically as you approach the limit. It clears older tool outputs first, then summarizes the conversation if needed. Your requests and key code snippets are preserved; detailed instructions from early in the conversation may be lost." Steering: "add a 'Compact Instructions' section to CLAUDE.md or run /compact with a focus" (how-claude-code-works). The costs page gives the CLAUDE.md form verbatim: `# Compact instructions` / "When you are using compact, please focus on test output and code changes". What survives (context-window page table): project-root CLAUDE.md and unscoped rules "Re-injected from disk"; auto memory "Re-injected from disk"; plan-mode plan "Re-injected from disk"; `paths:` rules and nested CLAUDE.md "reloaded on demand" (so their content is summarized away); "Files Claude read or edited: Claude Code re-reads up to five, most recently modified first", and "A file over 5,000 tokens comes back as a path reference without its content"; "Invoked skill bodies: Re-injected, capped at 5,000 tokens per skill and 25,000 tokens total; oldest dropped first", truncation "keeps the start of the file, so put the most important instructions near the top of SKILL.md"; "Context that hooks added earlier: Summarized with the rest of the conversation"; SessionStart hooks matching `compact` run and their output is added; background subagents keep running. The skill listing "is not re-injected after /compact. Only skills you actually invoked get preserved." The summary itself "keeps: your requests and intent, key technical concepts, files examined or modified with important code snippets, errors and how they were fixed, pending tasks, and current work" (context-window simulation text). The summarization request "inherits your session's extended thinking configuration" (v2.1.198+). A warm-cache /compact "costs a fraction of what the context size suggests"; a cold one "reprocesses the full history as uncached input" (prompt-caching). Thrashing: if "a file or tool output immediately refilled the context window several times in a row", Claude Code stops auto-compacting; recovery is read in chunks, `/compact keep only the plan and the diff`, move to a subagent, or `/clear` (troubleshooting). Partial compaction: `/rewind` then "Summarize from here" or "Summarize up to here" (best-practices).

**Thresholds and windows.** "If you don't set an auto-compact window, Claude Code compacts when the conversation reaches the model's context limit", except: "Cloud sessions compact as the conversation approaches the model's limit"; Sonnet 4.6/Opus 4.6 without extended context "compact at the 200K boundary"; native-1M models (Fable, Sonnet 5+, Haiku 5.5, Opus 4.7+) "compact before the window fills, at about 967K tokens by default" (model-config). Window override: `/autocompact 500k`, `autoCompactWindow`, `--autocompact`, or `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, range "100K to 1M tokens"; `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` (1-100) compacts earlier, "can't raise the threshold", and "Applies to main conversations and subagents" (env-vars). Unrecognized model IDs assume 200k unless `CLAUDE_CODE_MAX_CONTEXT_TOKENS` is set. `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` limits native-1M models to 200K. The 1M window "uses standard model pricing with no premium for tokens beyond 200K, except on Haiku 5.5, which costs more on prompts longer than 100K tokens". Raising `CLAUDE_CODE_MAX_OUTPUT_TOKENS` "reduces the effective context window before auto-compaction triggers".

**/context and startup cost.** "Run /context to see what's using space"; `/context all` shows per-MCP-tool tokens (features-overview). The context-window simulation's representative startup numbers: system prompt 4,200 tokens, MEMORY.md 680, environment 280, MCP tool names (deferred) 120, skill descriptions 450, CLAUDE.md 1,800. "MCP tool definitions are deferred by default ... only tool names and server instructions consume context until Claude uses a specific tool"; `ENABLE_TOOL_SEARCH=auto` loads schemas upfront "when they fit within 10% of the context window".

**Memory.** CLAUDE.md hierarchy: managed policy (`/etc/claude-code/CLAUDE.md` on Linux), user `~/.claude/CLAUDE.md`, project `./CLAUDE.md` or `./.claude/CLAUDE.md`, `CLAUDE.local.md`; "files in the directory hierarchy above the working directory are loaded at launch. Files in subdirectories load on demand" when Claude reads/writes a file there. "All discovered files are concatenated into context rather than overriding each other, ordered from broadest scope to most specific" (glossary). "Size: target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." "Imports help you organize a long file but don't reduce its context cost, because imported files also load at launch"; `@path` imports recurse "with a maximum depth of four hops". "Claude Code loads a CLAUDE.md file of up to 4 MiB in full and skips a larger file." `.claude/rules/*.md` load every session, or only when `paths:` frontmatter matches. Editing CLAUDE.md mid-session "doesn't apply ... The new content loads on the next /clear, /compact, or restart" (prompt-caching). Auto memory: directory `~/.claude/projects/<project>/memory/` with `MEMORY.md` index plus topic files; "The first 200 lines of MEMORY.md, or the first 25KB, whichever comes first, are loaded at the start of every conversation"; Claude Code warns when near the limit and errors when over it; "a session in a self-hosted environment runs with auto memory off by default"; `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` disables; it "isn't loaded into subagents" except forks (memory page).

**Tasks tool.** `TaskCreate/TaskGet/TaskList/TaskUpdate` are "available by default only on Opus 4.7, Sonnet 4.6, Haiku 4.5, and earlier models"; "On newer models, Claude keeps track of multi-step work without a written checklist, and the tools' definitions and reminders take up context"; opt in with `--allowedTools TaskCreate`; `CLAUDE_CODE_TASK_LIST_ID` shares a list across sessions (tools-reference, env-vars). So on Fable/Opus 5.5 the plugin cannot assume the Tasks tool exists; a file-based ledger is the portable equivalent.

**Hooks that prune or inject context.** `SessionStart` (matchers `startup|resume|clear|compact|fork`): `hookSpecificOutput.additionalContext` lands "at the start of the conversation, before the first prompt", and plain stdout also enters context; the `compact` matcher is the documented way to re-inject state after compaction. `UserPromptSubmit`: `additionalContext` "alongside the submitted prompt", can block, "can't replace the prompt"; default timeout 30 s and output is discarded on timeout. `PostToolUse`: `additionalContext` "next to the tool result" and `updatedToolOutput` "Replaces the tool's output with the provided value before it is sent to Claude"; "For redaction or transformation use cases, intercept at PreToolUse for outbound tool inputs and PostToolUse for inbound tool results"; the costs page's example rewrites a test command to `grep -A 5 ... | head -100`, "reducing context from tens of thousands of tokens to hundreds". `PreCompact` (matchers `manual|auto`) receives `trigger` and `custom_instructions` (the `/compact` text, `null` for auto); it can block compaction (exit 2) but its stdout "goes to the debug log", so it cannot add instructions. `PostCompact` receives `compact_summary` and "can't affect the compaction result". Hook output "over 10,000 characters is saved to a file; Claude gets a preview and the file path instead" (context-window). Hooks cost "Zero, unless the hook returns output".

**Skills.** "a skill's body loads only when it's used"; descriptions always load unless `disable-model-invocation: true`; "the combined description and when_to_use text is truncated at 1,536 characters"; "Keep SKILL.md under 500 lines. Move detailed reference material to separate files"; "Once a skill loads, its content stays in context across turns, so every line is a recurring token cost"; scripts are "executed, not loaded". `context: fork` runs the skill as a subagent prompt ("doesn't see your conversation history"), `agent:` defaults to `general-purpose`, `background` default true. Skill `model` for one turn is a model switch that "reads the entire conversation history with no cache hits" (prompt-caching). In subagents, `skills:` are "fully preloaded into its context at launch", up to 32 names.

**Subagents.** "Each subagent starts with a fresh, isolated context window. It doesn't see your conversation history, the skills you've already invoked, or the files Claude has already read." A non-fork subagent gets: its own system prompt (not the Claude Code one), the task message, the full CLAUDE.md hierarchy (unless `omitClaudeMd`; Explore/Plan skip it), git status, preloaded skills. It never gets output style, auto memory, or the parent's window size: "a subagent's context window is sized by its own model, not the parent's". Return path: "only the relevant summary returns to your main conversation"; reports are scanned and may get a `[harness: subagent output matched instruction-shaped pattern(s):` marker; a foreground API error returns "partial output with a note that the subagent was cut off". Forks inherit everything and share the parent's cache; non-forks have a separate cache and get the 5-minute TTL "even on a subscription". Model resolution: per-invocation `model` > frontmatter `model` (`inherit` = main model) > `CLAUDE_CODE_SUBAGENT_MODEL` > main model; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` overrides all. Built-ins: Explore uses the main model (with Fable exceptions), claude-code-guide uses Haiku. Subagents "inherit the main conversation's extended thinking configuration" (v2.1.198+). `effort` frontmatter: `low|medium|high|xhigh|max`. Limits: nesting depth 3 (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`), 20 concurrent (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`), 10 parallel read-only tools/subagents (`CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY`), descriptions over 15,000 tokens combined warn at startup, `maxTurns` returns partial output that can be resumed via `SendMessage`, auto-compaction fires inside subagents (`autoCompactWindow` frontmatter 100000-1000000). Background subagents "run with a smaller built-in tool set" (Read, Grep, Glob, Bash, Edit, Write, Skill plus all MCP tools). Fork mode is on by default in interactive sessions and off in `-p`/SDK.

**Effort and model.** Levels: Fable 5.1/5, Opus 5.5, Sonnet 5.5, Haiku 5.5, Opus 5, Sonnet 5, Opus 4.8/4.7: `low|medium|high|xhigh|max`; Opus 4.6/Sonnet 4.6 lack `xhigh`. Default `high`, except `medium` on Opus 5.5/Sonnet 5.5/Haiku 5.5 and `xhigh` on Opus 4.7. "`max` may show diminishing returns and is prone to overthinking". "In Anthropic's testing, Opus 5.5 at medium matches or exceeds Opus 5 at high". Changing effort mid-session invalidates the cache on most models, but not on Opus 5.5/Sonnet 5.5/Haiku 5.5/Fable 5.1 with an API key or subscription. Extended thinking "can't be turned off" on Opus 5.5, Sonnet 5.5, Haiku 5.5, or Fable; `MAX_THINKING_TOKENS` is ignored by adaptive-reasoning models, "so use effort levels there instead" (costs).

Anthropic's "Effective context engineering for AI agents" frames all of this: "find the smallest possible set of high-signal tokens that maximize the likelihood of some desired outcome"; context rot means "Context ... must be treated as a finite resource with diminishing marginal returns"; the three long-horizon techniques are compaction ("the first lever"), structured note-taking ("a NOTES.md file"), and sub-agents that "return only a condensed, distilled summary of its work (often 1,000-2,000 tokens)". Claude Code is cited as the hybrid: "CLAUDE.md files are naively dropped into context up front, while primitives like glob and grep allow it to navigate its environment and retrieve files just-in-time". The Claude Code team's caching post adds the engineering rule: "Don't change tools or models mid-conversation. Use tools to model state transitions ... Defer tool loading instead of removing tools", and "If you need to switch models, the best way to do it is with subagents".

### Q3a. Write results to files and return a short summary, or return full results in chat?

Confidence: high. Anthropic's research-system appendix: "Subagent output to a filesystem to minimize the 'game of telephone' ... Subagents call tools to store their work in external systems, then pass lightweight references back to the coordinator. This prevents information loss during multi-stage processing and reduces token overhead from copying large outputs through conversation history." Claude Code docs: the subagent's "tool calls stay out of your context, and Claude gets back a summary"; the cost of anything returned is paid "on every subsequent message" because "Claude Code sends your full conversation with every request". Superpowers (installed, 7.0.0) encodes the same rule: "Everything you paste into a dispatch prompt — and everything a subagent prints back — stays resident in your context for the rest of the session and is re-read on every later turn. Hand artifacts over as files", and its implementer "writes the full report there and returns only status, commits, a one-line test summary, and concerns". Caveat from the same post: direct-to-file is best "for structured outputs like code, reports, or data visualizations where the subagent's specialized prompt produces better results than filtering through a general coordinator"; the lead still needs enough in the summary to decide the next step.

### Q3b. When does a fresh subagent context beat continuing in the main context?

Confidence: high. Use a subagent "when a side task would flood your main conversation with search results, logs, or file contents you won't reference again" (sub-agents); "A side task floods your conversation with output you won't reference again -> Route it through a subagent" (features-overview); "After two failed corrections, /clear and write a better initial prompt" and "A clean session with a better prompt almost always outperforms a long session with accumulated corrections" (best-practices). Anthropic research system: multi-agent "outperformed single-agent Claude Opus 4 by 90.2%" on breadth-first research, because subagents "operating in parallel with their own context windows" let the system "spend enough tokens to solve the problem" (token usage explains 80% of BrowseComp variance). Fresh context also removes bias: "A fresh context improves code review since Claude won't be biased toward code it just wrote." Continue in main context when the task "requires extensive back-and-forth" (compaction "maintains conversational flow") or when, per Cognition, actions "carry implicit decisions" that must be consistent with everything else (see Q3g). A fork is the middle path: full history, shared cache, "costs less than a fresh subagent for tasks that need the same context".

### Q3c. How much does tool output cost and how do you trim it?

Confidence: high on limits, medium on typical sizes. Documented caps (all per call): `WebFetch` "reads up to 100,000 characters of a page's content per call", runs the prompt "in a separate model call, and Claude receives the result of that call rather than the raw page" ("lossy by design"), caches 15 minutes; `WebSearch` "returns result titles and URLs. It doesn't fetch the result pages"; `Read` "at most 25,000 tokens" (`CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS`), refuses whole files over 256 KB, `allow_large` sized against remaining window; Bash inline "roughly 30,000 characters", beyond that "the path of a file saved to the session directory ... plus a preview of up to the first 2,000 characters" (`BASH_MAX_OUTPUT_LENGTH` up to 150,000); MCP responses `MAX_MCP_OUTPUT_TOKENS` default 25,000, warning above 10,000 tokens, text results over 50,000 characters saved to a file; hook output over 10,000 characters saved to a file; Glob capped at 100 files. Observed this session: a full Claude Code docs page is 100-270k characters (hooks page 270,831), so a single raw fetch can approach a whole 200K-token budget; WebFetch's extraction step returned 3-15k-character answers instead. Trimming: fetch "with objectives" (WebFetch prompt; Exa `objective`/`maxCharacters`; Parallel `objective` excerpt mode, with `full_content` warned to return "tens of thousands of tokens"); grep saved tool-result files instead of re-reading; PreToolUse command rewriting (`grep -A 5 ... | head -100`); PostToolUse `updatedToolOutput` for inbound results. Snapshot vs screenshot: Playwright's `browser_snapshot` tool description says it "is better than screenshot"; images also hit the API's image-count cap, after which Claude Code "removes a batch of the oldest images" and reprocesses the conversation from that point (prompt-caching), so text snapshots are both smaller and cache-safer. The research-system post's effort rule caps call counts: "Simple fact-finding requires just 1 agent with 3-10 tool calls, direct comparisons might need 2-4 subagents with 10-15 calls each".

### Q3d. Rules of thumb for CLAUDE.md and skill size

Confidence: high. CLAUDE.md: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence" (memory); "Aim to keep CLAUDE.md under 200 lines by including only essentials" (costs); "If Claude keeps doing something you don't want despite having a rule against it, the file is probably too long and the rule is getting lost"; "If you emphasize many lines, none of them stands out"; `/doctor` proposes trims (best-practices). Imports do not reduce cost. Skills: "Keep SKILL.md under 500 lines"; descriptions truncated at 1,536 characters; only the first 5,000 tokens of an invoked skill survive compaction, 25,000 tokens total. MEMORY.md: 200 lines / 25KB. Subagent descriptions: 15,000 tokens combined. Anthropic's guidance: system prompts at "the right altitude", "minimal does not necessarily mean short", prefer "diverse, canonical examples" over "a laundry list of edge cases".

### Q3e. Do structured JSON/markdown schemas for subagent returns measurably help merging?

Confidence: low (no measured result found). Supporting evidence is prescriptive: "Each subagent needs an objective, an output format, guidance on the tools and sources to use, and clear task boundaries. Without detailed task descriptions, agents duplicate work, leave gaps, or fail to find necessary information" (research-system); Anthropic's harness post chose JSON for the feature list because "the model is less likely to inappropriately change or overwrite JSON files compared to Markdown files"; superpowers specifies a "report contract" and that subagent reports are "scanned" for instruction-shaped text by Claude Code before the lead reads them. Claude Code's own `ReportFindings` tool exists so findings render "as a structured list ... instead of printing them as text". No source quantifies merge quality with vs without a schema; the repo's `_FORMAT.md` is the right place to fix one and observe.

### Q3f. Re-reading large files vs keeping an index

Confidence: medium. Each Read costs its tokens again and stays in history; after compaction "Claude Code re-reads up to five" files and anything "over 5,000 tokens comes back as a path reference without its content", so large files are the first thing lost. Anthropic recommends agents "maintain lightweight identifiers (file paths, stored queries, web links, etc.) and use these references to dynamically load data into context at runtime", using "head and tail to analyze large volumes of data without ever loading the full data objects into context". Claude Code's own index pattern is `MEMORY.md`: "Index, one line per memory, loaded into every session", with detail in topic files, hard-capped at 200 lines. Prompt caching does not help here: "There is no per-file or per-segment caching"; a file read is new conversation tokens every time it is re-read, cached only as part of the growing prefix.

### Q3g. When not to use subagents

Confidence: high. Overhead: "Each subagent spends tokens of its own"; "agents typically use about 4x more tokens than chat interactions, and multi-agent systems use about 15x more tokens than chats"; agent teams "approximately 7x more tokens than standard sessions"; superpowers: "Turn count beats token price ... the cheapest models routinely take 2-3x the turns on multi-step work — costing more overall" and "Batch small same-shape work" into one dispatch. Cognition's argument: "Share context, and share full agent traces, not just individual messages" and "Actions carry implicit decisions, and conflicting decisions carry bad results"; parallel subagents that make design decisions produce "a bird and background with completely different visual styles". Cognition explicitly carves out the read-only case: Claude Code's subtask agent "is usually only tasked with answering a question, not writing any code ... The benefit ... is that all the subagent's investigative work does not need to remain in the history of the main agent". Anthropic agrees on scope: multi-agent fits "breadth-first queries", not "domains that require all agents to share the same context or involve many dependencies between agents"; early failures were "spawning 50 subagents for simple queries". Superpowers' "Don't use when": related failures, "Need to understand full system state", "Exploratory debugging", shared state. Plan mode guidance generalizes: "If you could describe the diff in one sentence, skip the plan."

## Implications for the researcher plugin

Each rule names where it lives and the evidence behind it.

1. **Lead holds only plan, index, and status lines (CLAUDE.md).** "What the lead may hold in context: `research/plan.md`, `research/findings/INDEX.md`, one-line status per question, and the last subagent summary. Never a fetched page, a raw search result, or a full findings file." Evidence: full history is re-sent every turn (costs); compaction drops early instructions (how-claude-code-works); Chroma shows focused (~300-token) inputs beat full (~113k) ones; Anthropic: lead "focuses on synthesizing".
2. **One findings file per question, written by the subagent, returned as a path plus a summary of at most ~20 lines (agent definitions).** Enforce a report contract: `path`, 5-10 bullet findings, open questions, confidence. Evidence: "pass lightweight references back to the coordinator" (research-system); subagent summaries "1,000-2,000 tokens" (context-engineering); superpowers report-file contract.
3. **Keep an `INDEX.md` the lead re-reads instead of findings files (CLAUDE.md + skill).** One line per question/source, under 200 lines, same shape as `MEMORY.md`. Evidence: MEMORY.md index pattern and its 200-line/25KB cap; "lightweight identifiers" (context-engineering); only 5 files, each under 5,000 tokens, come back after compaction (context-window).
4. **Progress ledger file written after every subagent returns, read first after any compaction (CLAUDE.md compact section + SessionStart `compact` hook).** Add `# Compact instructions: keep the question list with status, the paths of all findings files, the names of running subagents, and any rulings; drop fetched page contents.` Optionally a SessionStart hook with `matcher: compact` that echoes `INDEX.md`'s first 30 lines as `additionalContext`. Evidence: "Compact Instructions" section is the documented steering point; SessionStart `compact` output "adds their output to the compacted context"; PreCompact cannot inject instructions; harness post: start each session from `claude-progress.txt` and git log; superpowers: "trust the ledger and git log over your own recollection".
5. **Project-root CLAUDE.md under 200 lines, no imports, no procedures (CLAUDE.md).** Procedures go to skills (`research/`-scoped rules may use `paths:` only if they need not survive compaction). Evidence: 200-line guidance from three pages; imports "don't reduce its context cost"; `paths:` rules are "summarized away"; "Bloated CLAUDE.md files cause Claude to ignore your actual instructions".
6. **Skills under 500 lines, critical steps in the first ~5,000 tokens, reference material in sibling files (skills).** Evidence: "Keep SKILL.md under 500 lines"; compaction keeps "the first 5,000 tokens of each" invoked skill; descriptions cut at 1,536 characters.
7. **Tool-output caps in every agent prompt: fetch with an objective, never dump a page; one WebFetch/Exa call per page with a specific prompt; `maxCharacters` <= 8,000 unless quoting; prefer accessibility snapshot over screenshot; grep saved tool-result files rather than re-reading them.** Evidence: WebFetch 100,000 chars/call and lossy extraction; Parallel `full_content` warning; image eviction and cache reprocessing; MCP 25,000-token cap and 50,000-char file save; costs page's hook that filters output "from tens of thousands of tokens to hundreds".
8. **Spawn-vs-inline rule (CLAUDE.md, one paragraph).** Inline when the answer is one tool call or the lead needs the raw result to decide; spawn a fresh subagent when a question needs 3+ fetches or any page read, when results won't be referenced again, or when an independent check is wanted. Scale effort: 1 agent with 3-10 calls for a fact, 2-4 agents with 10-15 calls each for a comparison, more only with "clearly divided responsibilities". Never let research subagents spawn further subagents. Evidence: research-system effort rules and "spawning 50 subagents for simple queries"; "side task floods your conversation" trigger; superpowers no-subagents contract ("every reviewer a worker spawned duplicated the task review"); Cognition's read-only carve-out.
9. **Subagents do reading and drafting, not cross-question decisions (agent definitions).** Any decision that must be consistent across questions (terminology, verdicts, requirement wording) is made by the lead and written to the ledger before dispatch. Evidence: Cognition Principles 1-2; Anthropic: multi-agent unsuited where tasks "involve many dependencies between agents".
10. **Always set `model:` and `effort:` explicitly per agent; mechanical fetch-and-extract agents on `haiku`/`sonnet` at `medium`, synthesis and review on the strongest model at `high`; never change the lead's model or effort mid-run.** Evidence: subagent model order defaults to the main (most expensive) model; superpowers "Always specify the model explicitly"; "Turn count beats token price"; Opus 5.5 `medium` "matches or exceeds Opus 5 at high"; model/effort switches invalidate the cache; "switch models ... with subagents" (caching post).
11. **Fresh dispatch prompts: task, interfaces, file paths, report contract. No pasted history.** Evidence: superpowers' observed 42k-char dispatch "of which 99% was pasted history"; subagents load CLAUDE.md themselves so rules need not be repeated; "Keep spawn prompts focused" (costs).
12. **Batch same-shape lookups into one dispatch; cap concurrency at 3-5 parallel agents.** Evidence: superpowers "Batch small same-shape work"; research-system "3-5 subagents in parallel" cut time "up to 90%"; `CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY` default 10, 20 concurrent subagents hard cap.
13. **Compact deliberately at phase boundaries (`/compact` with focus) rather than waiting for auto-compaction mid-synthesis; in cloud sessions expect earlier compaction.** Evidence: "run /compact at a natural break"; cloud sessions "compact as the conversation approaches the model's limit"; warm-cache compaction is cheap, cold is full price.
14. **Do not rely on the Tasks tool, auto memory, or a 1-hour subagent cache in cloud sessions.** Evidence: Task tools absent by default on newer models; auto memory off in self-hosted environments; subagents get 5-minute TTL unless `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL=1h`.
15. **Hooks only for deterministic trimming and re-injection, never for prose rules.** Candidates: PreToolUse rewriting `curl`/log commands to `head`/`grep`; PostToolUse `updatedToolOutput` truncating oversized MCP results; SessionStart `compact` re-injecting the index. Evidence: hooks "Zero" context unless they return output; "Put guardrails in hooks"; PreCompact stdout goes to debug log.
