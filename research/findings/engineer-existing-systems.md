## Questions and answers

### How does the engineer map a codebase through subagents without the lead holding files?

Confidence: medium (practice is well documented by Anthropic; accuracy of a subagent-written map versus one long context is not measured by any opened source).

**The constraint and the pattern.** Claude Code's best-practices page names the failure: "The infinite exploration. You ask Claude to “investigate” something without scoping it. Claude reads hundreds of files, filling the context." and the remedy: "Delegate research with `"use subagents to investigate X"` . They explore in a separate context, keeping your main conversation clean for implementation." (https://code.claude.com/docs/en/best-practices). Anthropic's context-engineering post favours just-in-time loading, where agents "maintain lightweight identifiers (file paths, stored queries, web links, etc.)", says good context engineering "means finding the smallest possible set of high-signal tokens", and gives the return size: "Each subagent might explore extensively, using tens of thousands of tokens or more, but returns only a condensed, distilled summary of its work (often 1,000-2,000 tokens)." (https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents). The same post says Claude Code's "primitives like glob and grep allow it to navigate its environment and retrieve files just-in-time, effectively bypassing the issues of stale indexing and complex syntax trees." The multi-agent research post gives the delegation brief: "Each subagent needs an objective, an output format, guidance on the tools and sources to use, and clear task boundaries.", and the hand-back rule: "Subagents call tools to store their work in external systems, then pass lightweight references back to the coordinator." (https://www.anthropic.com/engineering/multi-agent-research-system). Claude Code ships a read-only Explore agent, "A fast, read-only agent optimized for searching and analyzing codebases.", which can be redefined with `model: haiku` "to run exploration on a lower-cost model."; each subagent "starts with a fresh, isolated context window. It doesn't see your conversation history, the skills you've already invoked, or the files Claude has already read."; and the docs warn "Running many subagents that each return detailed results can consume significant context, and each subagent spends tokens of its own while it runs." (https://code.claude.com/docs/en/sub-agents).

**Deterministic seeds.** No single tool gives a trustworthy whole-system map. Aider's repo map fits a token budget ("The token budget is influenced by the `--map-tokens` switch, which defaults to 1k tokens.") and "only includes the most important identifiers, the ones which are most often referenced by other portions of the code." (https://aider.chat/docs/repomap.html); Aider moved from ctags to tree-sitter because "The map is richer, showing full function call signatures and other details straight from the source files." (https://aider.chat/2023/10/22/repomap.html, 2023). Exact graphs come from language tools: pydeps prints "a json formatted list of module names" for a Python package's externals (https://pythonhosted.org/pydeps/index.html); madge "is a developer tool for generating a visual graph of your module dependencies, finding circular dependencies" (https://github.com/pahen/madge); dependency-cruiser does "Validate and visualise dependencies. With your rules. JavaScript. TypeScript." (https://github.com/sverweij/dependency-cruiser). Sourcegraph precise navigation "requires language-specific indexes to be generated and uploaded" (https://docs.sourcegraph.com/code_intelligence/explanations/precise_code_intelligence) and otherwise "uses a mix of text search and syntax-level heuristics (no language-level semantic information)" (https://sourcegraph.com/docs/code-navigation); scip-typescript wants the project root "containing tsconfig.json" (https://github.com/kernoio/scip-typescript, a fork listing). CodeQL creates databases without a build for Python and JS/TS ("`none`: The database will be created without building the source root. Available for C#, Java, JavaScript/TypeScript, Python, and Ruby.", https://docs.github.com/en/code-security/reference/code-scanning/codeql/codeql-cli-manual/database-create) and holds "queryable data extracted from a codebase, for a single language at a particular point in time." (https://codeql.github.com/docs/codeql-overview/about-codeql/). Semgrep matches syntax patterns where "The `...` ellipsis operator abstracts away a sequence of zero or more items" (https://semgrep.dev/docs/writing-rules/pattern-syntax). DeepWiki is capped at "Maximum 30 pages (80 for enterprise)" and the public tier gives "basic documentation and Q&A capabilities." (https://docs.devin.ai/work-with-devin/deepwiki).

**What the research says about accuracy and cost.** SWE-Explore (June 2026) finds "current agents are strong at finding relevant files but remain recall-limited at the line level", that "Sparse retrievers (BM25, TF–IDF) and the lightweight dense retriever remain close to Random on most metrics", and its benchmark is "Python 547 64.5 Go 84 9.9 JavaScript 51 6.0" so TypeScript evidence is thin (https://arxiv.org/pdf/2606.07297). SWE-QA-Pro: "agentic workflows significantly outperform direct answering (e.g., a ~13-point gap for Claude Sonnet 4.5)" (https://aclanthology.org/2026.findings-acl.837). FastContext's read/glob/grep explorer subagent "improve[s] resolution accuracy up to 5.5% while reducing main model token consumption up to 60%", with "the explorer accounting for only 2.1% of that total", and its direct main-agent baseline cost "| Direct main | 457k / task | $282.47 |" (https://arxiv.org/html/2606.14066v1). DocAgent builds an AST dependency DAG and processes modules in topological order with Reader/Searcher/Writer/Verifier agents; "Our ablation study confirms the vital role of the topological processing order." (https://aclanthology.org/2025.acl-demo.44.pdf). Anthropic reports multi-agent beat single-agent "by 90.2% on our internal research eval" but "most coding tasks involve fewer truly parallelizable tasks than research", and "multi-agent systems use about 15× more tokens than chats" (https://www.anthropic.com/engineering/multi-agent-research-system). The ETH Zurich study (Feb 2026) found "context files tend to reduce task success rates compared to providing no repository context, while also increasing inference cost by over 20%.", that "context files, even developer-provided ones, are not effective at providing a repository overview.", that "human-written context files should describe only minimal requirements.", and that where documentation is missing "LLM-generated context files not only consistently improve performance by 2.7% on average, but also outperform developer-written documentation." (https://arxiv.org/pdf/2602.11988.pdf). For the map's shape, SWE-Explore notes "missing core evidence hurts more than moderate redundant context." (https://arxiv.org/pdf/2606.07297) and FastContext's explorer returns "file paths, line ranges, and short relevance notes." (https://arxiv.org/html/2606.14066v1).

**Finding why something breaks.** The sub-agents page: "Running tests, fetching documentation, or processing log files can consume significant context." and "Use a subagent to run the test suite and report only the failing tests with their error messages" (https://code.claude.com/docs/en/sub-agents); best practices: `claude -p "Analyze this log file" --output-format stream-json --verbose` and "If you can’t verify it, don’t ship it." (https://code.claude.com/docs/en/best-practices). Claude Code exports its own OpenTelemetry traces, with subagent spans nested "under the parent's claude_code.tool span", but "An OpenTelemetry-instrumented application that you run through the Bash tool doesn't inherit Claude Code's exporter endpoint or headers", repository settings cannot enable it ("Claude Code ignores the OpenTelemetry exporter variables in a repository's .claude/settings.json and .claude/settings.local.json"), and `claude --debug-file <path>` writes a debug log (https://code.claude.com/docs/en/monitoring-usage); Agent SDK tracing "is in beta. Span names and attributes may change between releases." (https://code.claude.com/docs/en/agent-sdk/observability).

**Worker inferences (codebase-mapping note).** A precomputed map is a seed that tells subagents where to look, and its facts (import edges, symbol locations) should come from deterministic tools, not from an LLM reading files; CodeQL and Semgrep answer targeted questions (who calls X, where are HTTP calls or secrets) and are not map generators. Run the script graph first, split modules along it leaf-first as DocAgent does, give each read-only subagent one module, have it write a fixed-schema note and return a path plus a 5-10 line status, then an integration subagent merges notes and a verifier subagent re-opens a sample of cited lines. Per-module note schema, every fact with `path:line`: purpose; entry points (CLI, routes, handlers, cron or workflow triggers); imports in and out from the script graph; data stores touched with read or write; external calls; credential names referenced (never values); tests and last result; build and run commands; known breakages as symptom, evidence path, first-seen, reproduction command; a confidence tag per fact (script-derived, read-verified, inferred). Keep the map out of CLAUDE.md and load it by path. Cheap observability order: read existing logs and run histories through a subagent returning error-pattern counts, reproduce with a failing test, and only then add app-side OTel (the app-side step has no opened source). Worker inference (not in the source): a mid-size repo map costs hundreds of thousands of subagent tokens and 1-2k tokens per module back to the lead; the note derives this from FastContext's 457k-per-task figure (a whole solve, GPT-5.4) and Anthropic's 1,000-2,000 token returns and marks it an estimate to measure.

**Contradictions.** Anthropic describes grep/glob exploration as "bypassing the issues of stale indexing" (https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) while Aider and Sourcegraph build precomputed maps and indexes to help the agent (https://aider.chat/docs/repomap.html, https://docs.sourcegraph.com/code_intelligence/explanations/precise_code_intelligence); the worker calls it not a hard conflict (Anthropic also names a hybrid) and no source compares them on one repo, so it is unresolved and in the spike list. Claude Code's own guidance advocates context files with an overview, while https://arxiv.org/pdf/2602.11988.pdf reports they do not help as overviews; the worker notes the effect sizes are small (-3% / +4%) and the tasks are SWE-bench-style bug fixes, not a pre-change audit, so transfer is untested. Anthropic's 90.2% multi-agent gain is on research tasks (https://www.anthropic.com/engineering/multi-agent-research-system) and FastContext's coding gain is 0.0 to 5.5 points (https://arxiv.org/html/2606.14066v1); the gains do not carry over in size, and no source measures per-module subagent mapping against one long context.

### How does the engineer inventory credentials without leaking them, and reconcile competing sources of truth and dirty data?

Confidence: medium-high for the credential layers (deny-rule enforcement has a reported bug, so spike it); medium for reconciliation.

**Credentials: two layers.** Hard gates first. Claude Code's settings example says "`Read(./.env)` on its own stops the file tools and commands that name the file, such as `cat .env`, but not [`grep -r` run over the directory]" and that "the `sandbox` block in this file closes that gap, because the sandbox [adds your `Read` deny paths] to what every sandboxed command can't read." (https://code.claude.com/docs/en/settings-example). A Feb 2026 issue reported the opposite: "The `Read` tool call succeeds despite matching the deny pattern. The full contents of `.env.local` ... are read and displayed." (https://github.com/anthropics/claude-code/issues/24846, closed as duplicate of #6699). Then inventory by metadata. Gitleaks can "redact secrets from logs and stdout. To redact only parts of the secret just apply a percent value from 0..100." and scans a directory with `gitleaks dir -v path_to_directory_or_file` (https://github.com/gitleaks/gitleaks). TruffleHog's default verification means "verified: Credential confirmed as valid and active by API testing", and the flag text "Don't verify the results." turns it off (https://github.com/trufflesecurity/trufflehog). n8n's API scopes include "`credential:list` | List credentials.", "`credential:read` | Retrieve a credential and its data schema." and "`securityAudit:generate` | Generate a security audit report for the instance." (https://docs.n8n.io/connect/n8n-api/authentication), and n8n's own public-API design rule is "GET never returns the real secret; it returns that sentinel (or omits the field)."
