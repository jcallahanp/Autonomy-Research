# Self-improvement round 1: plan

Date: 2026-10-16. Base: merge commit 981a205 on main (v0.1).
Series: 1, round 1 of 2.
Evidence: `research/findings/research-agent-self-improvement.md` (the plugin's own research run)
and `research/runs/research-agent-self-improvement/hand-check.md` (20-citation hand check).

## Loop rules for this round

- The exam is frozen: the 10 cases in `plugin/evals/` as of 981a205. A hash manifest
  (`tests/frozen-exam.sha256`) makes any edit to them fail `tests/check.sh` and CI.
- A change is kept only if the frozen fast exam does not drop (paired, 3 runs per case, same
  model) and the findings file or hand check gives a specific reason for it.
- New cases are added beside the frozen ones with the tag `tail`. They are written by the same
  author as the fixes, so they are development cases, not a holdout, and are reported
  separately from the frozen score.
- At most 2 rounds. Each ends in a PR with before/after numbers; John's merge is the only
  sign-off.

## Changes

Each line: the change, the file(s), and the reason in the findings.

1. **Verifier can open what researchers cite.** Add Firecrawl scrape to its tools; check repo
   `path:line` citations with Read; cap the sample at 20, chosen by risk (numbers, quotes,
   single-source and summary claims first); an uncertain judgment counts as unverified.
   `agents/verifier.md`. Reason: verifier lacks the tools researchers used, sample can exceed 20
   (internal-audit rank 1); judges agree only moderately, so uncertain = fail
   (citation-faithfulness).
2. **Quote carry-through.** Every claim in a note carries a verbatim `Quote:` of at most 30
   words from the opened source; the synthesizer copies claim, quote and URL together and adds
   no information that is not backed by a cited line. `skills/research/note-schema.md`,
   `agents/researcher.md`, `agents/synthesizer.md`, `skills/research/findings-format.md`.
   Reason: most citation errors arise at the merge stage; passing raw snippets raised precision
   (citation-faithfulness). This run's own hand check agrees: 2 of its 3 partly supported
   citations were introduced by the synthesizer (a citation narrowed, a claim strengthened).
3. **Repo citations are legal.** A claim about a cloned or local repo may cite
   `<repo or path>:<line>` read in the session; the synthesizer keeps such citations.
   `agents/synthesizer.md`, `agents/researcher.md`, `skills/research/note-schema.md`.
   Reason: synthesizer.md:24-26 drops what researcher.md:67-68 asks for (internal-audit rank 2).
4. **Compaction re-injects the active run.** The SessionStart hook (already fired on compact
   and clear) also injects the newest `research/runs/*/PLAN.md` whose Outputs still say pending
   or running, and the newest 30 INDEX lines instead of the first 30.
   `hooks/session-start.sh`. Reason: context-rot facet; hook injects only the first 30 INDEX
   lines (internal-audit rank 7).
5. **Workers expect compaction.** Researchers write the note skeleton first, fill it as they
   go, and are told they may be compacted and must not wrap up early. Dispatch prompts copy the
   PLAN.md Rulings line verbatim. `agents/researcher.md`, `skills/research/SKILL.md`.
   Reason: context-rot facet.
6. **Resolve the contradictions the run found in the plugin itself.**
   - `routing.md:13` vs `researcher.md:46` on Parallel full content: follow the researcher rule.
   - Registry rows: one owner. Spike rows are written by the synthesizer in spike mode; triage
     and tool-scan rows by the lead from ROW lines. Spike and repo-triage text say the same.
   - "Open questions" vs "Gaps": use the findings-format wording everywhere.
   Reason: synthesizer CONTRADICTIONS list.
7. **Pipeline-tail cases (new, tag `tail`).** Two offline cases with mocked pages:
   - `verify-tail`: a 2-facet run must end with PLAN.md Outputs filled, a `## Verification`
     section in the findings file, and an INDEX line for the slug.
   - `quote-carry`: the findings file carries a verbatim quote for a mocked fact, and a claim
     the mocked page does not support is absent.
   Reason: self-test cannot see the pipeline tail (internal-audit rank 3; eval-without-overfit).
8. **Frozen-exam guard.** `tests/frozen-exam.sha256` lists the 10 frozen cases' files;
   `tests/check.sh` fails on any change. Reason: eval-without-overfit (no grader or mock edits
   in the scored diff).
9. **A self-improve skill** that writes down this loop so a later session can run round 2
   without re-deriving it: frozen exam, tail cases, paired re-measure, keep rule, 2-round cap,
   changelog at `docs/self-improvement/`. `skills/self-improve/SKILL.md`, index entry.
   Reason: prompt-optimization-loops and eval-without-overfit facets.

10. **One-fact path with no fetch tool.** When no search or fetch tool exists, the lead says so,
   names the page to check, and spawns no worker (a worker has the same tools).
   `skills/research/SKILL.md`. Reason: a live run with web tools withheld showed the lead
   delegating a one-fact lookup to a general-purpose worker that had no tools either.
